All sources are presets on the **Addons** page. There is no separate Sources screen.

## Existing configurations and backups

AIOLiveTV keeps the existing `UserData` configuration format. Loading an old draft or importing a backup removes VOD-only settings such as release-quality rules, SeaDex, torrent/Usenet age and seeder filters, title/year/episode matching, autoplay, downloads and episode pre-caching. Movie/series sorting and cache sorting overrides are removed; supported global Live TV criteria retain their order and direction.

Empty disabled service entries and an unconfigured proxy are omitted. Services with credentials, configured proxies, Live TV deduplication rules, display settings, TMDB settings, formatter definitions, presets and channel mappings are preserved. Disabled or removed channels and manual stream URLs remain intact.

The same cleanup runs on the server before saving and when reading older saved configurations. Reading or importing does not rewrite the saved configuration; **Save** persists the cleaned draft. JSON exports use the same cleanup so reimporting them does not restore retired options. Keep your original backup if you also use those VOD settings in AIOStreams.

## XMLTV

XMLTV is a **catalog and meta** builtin. It does not play video.

| Option | Purpose |
| --- | --- |
| URL | HTTP(S) address of the `.xml` / `.xml.gz` guide |
| Timeout | Fetch timeout in milliseconds |
| EPG Time Shift | Minutes to add to every programme start/stop |
| Resources | Keep **Catalog** and **Meta** |

Use XMLTV when you want Native EPG. The addon advertises `behaviorHints.epgProvider` only after loading valid programmes attached to known guide channels. Empty guides, invalid programmes and download failures do not enable Native EPG. The TV catalog keeps the Stremio `date` extra.

Channel ids come from `tv/channel/@id`. Extra `<display-name>` entries become aliases. Programmes are grouped by channel id (case-insensitive).

## M3U

M3U is a **stream** builtin. It can also list channels when there is no EPG.

| Option | Purpose |
| --- | --- |
| URL | Playlist URL |
| Timeout | Fetch timeout |
| Resources | Catalog + Meta + Stream by default. Select **Stream** only to bind URLs onto channels that another source already listed. |

`tvg-id` on `#EXTINF` is the strongest match key against XMLTV. `tvg-name` and the display title are used when `tvg-id` is missing.

M3U **must not** set `epgProvider`. A playlist-only configuration stays a normal live catalog.

### Find an EPG in a playlist

In the M3U add/edit dialog, enter the playlist URL and choose **Find EPG guides**. AIOLiveTV reads `url-tvg`, `x-tvg-url` and `tvg-url` from the playlist header. Select the guides you want before choosing **Install** or **Update**. Each selected address becomes an ordinary XMLTV preset; existing guides are not duplicated or re-enabled. Cancelling the dialog does not add any guides. The changes stay in your draft until **Save**.

### Optional programme metadata from TMDB

Under **Addons → Marketplace → Metadata & Catalogs**, enable **Enrich EPG programmes with TMDB**. Use the instance credentials or supply your own API key/read token, and select a language. This sends eligible programme titles to TMDB.

Enrichment fills missing descriptions, artwork, genres and credits for confidently identified films and episodes. XMLTV content links to TMDB/IMDb and `xmltv_ns` episode numbers are supported. Title searches require an explicit production year or episode evidence and a unique exact normalized match. Broadcast dates are never treated as production years.

The original guide keeps its schedule, programme ids, transmission runtime and populated metadata. Requests use four concurrent lookups, at most 24 programmes per response (nearest to the current time), a 1.5-second response budget and the existing cache infrastructure. Successful lookups are cached for seven days; genuine misses for six hours. Upstream/authentication failures are not cached as misses. A failed lookup leaves the original programme available. Without EPG, this option does not generate a schedule or enable `epgProvider`.

### Catch-up compatibility

Catch-up playback is not exposed yet. In the Native EPG implementation referenced by this project, Stremio Web only attaches playback links to the currently airing programme: [Discover.js in PR #1218](https://github.com/Stremio/stremio-web/blob/d2522a1f4299974f0d0b440d276cc7e9a852f951/src/routes/Discover/Discover.js).

AIOLiveTV therefore returns no streams for a scheduled programme that is past, future or unknown, instead of silently playing the live channel. Direct channel playback remains available. Provider archive URL support should be implemented once an archive action can be exercised through the supported client flow.

## Xtream Codes

Xtream can supply catalog, meta (including EPG when the provider has it) and streams.

| Option | Purpose |
| --- | --- |
| Server URL | Base URL, for example `http://example.com:8080` |
| Username / Password | Account credentials |
| Stream format | `m3u8` (HLS), `ts`, or `rtmp` |
| Category ID | Optional live category; empty imports every live category |
| EPG Time Shift | Same as XMLTV |
| Resources | Catalog, Meta and Stream by default |

Treat credentials like any other secret stored in `UserData`. Prefer HTTPS to the Xtream panel when the provider supports it.

## TVHeadend

TVHeadend can supply catalog, meta (EPG) and live streams over its HTTP JSON API. Recordings, DVR scheduling, timeshift, HDHomeRun and Jellyfin bridges are out of scope.

**Server Access Required** — the AIOLiveTV instance must be able to reach the TVHeadend HTTP port. That is not the same as “only self-hosted AIOLiveTV”: a remote instance with VPN or a private route works; a public instance that cannot reach your LAN does not.

| Address | Who must reach it |
| --- | --- |
| **Server URL** (API) | The AIOLiveTV backend (channel list, EPG, tickets, proxy upstream) |
| **Playback URL** (optional) | The player device in **direct** mode (or leave blank to reuse the API URL) |
| Proxy stream URL on this instance | The player device in **proxy** mode; AIOLiveTV then reaches TVHeadend |

Private literals such as `192.168.x.x`, `localhost` or Docker service names resolve on the **instance network**, not automatically on your home LAN.

| Option | Purpose |
| --- | --- |
| Connection Name | Label in the Addons list |
| Server URL | Base URL used by AIOLiveTV for `/api/channel/grid`, `/api/epg/events/grid`, … |
| Username / Password | TVHeadend account (Basic auth). Empty if the server allows anonymous access |
| Playback URL | Player-facing base URL when it differs from the internal API URL |
| Playback Mode | **Direto** (short-lived ticket, no permanent password in the URL) or **Proxy** (video through AIOLiveTV, if the admin enabled it) |
| HTTP Profile | TVHeadend streaming profile (default `pass`; no transcoding in AIOLiveTV) |
| Tag / Group IDs | Optional comma-separated channel-tag UUIDs |
| Test Connection | Backend probe of `/api/channel/grid?limit=1` (does not start a tuner) |

### Instance policy

| Env | Default | Effect |
| --- | --- | --- |
| `TVHEADEND_ENABLED` | `true` | Disable the provider for everyone on this instance |
| `TVHEADEND_DISABLED_REASON` | English admin message | Shown as **Disabled by this instance administrator** |
| `HTTP_ALLOW_PRIVATE_URLS` | `false` | Required for API/playback URLs on private/reserved addresses |
| `TVHEADEND_PROXY_ENABLED` | `false` | Allow proxy playback (bandwidth on the instance) |

On public / multi-user hosts keep private URLs and proxy off. On a personal LAN or Docker network set `HTTP_ALLOW_PRIVATE_URLS=true`, and set `TVHEADEND_PROXY_ENABLED=true` only if players cannot reach TVHeadend directly.

Credentials stay on the backend. Direct mode uses TVHeadend playlist tickets (~5 minutes). Proxy mode streams with flow control and closes the upstream when the player disconnects. Prefer the `pass` profile; exotic containers may need `behaviorHints.notWebReady` on some Stremio clients.

## Pluto TV

Pluto TV is wired through **community** playlists and guides (not an official Pluto TV API):

| Role | Source |
| --- | --- |
| Live channels + streams (M3U) | [OwnerPlugins/pluto-tv-m3u](https://github.com/OwnerPlugins/pluto-tv-m3u) (`pluto-live-XX.m3u`, refreshed about every 6 hours) |
| Programme guide (XMLTV) | [matthuisman/i.mjh.nz](https://github.com/matthuisman/i.mjh.nz) (`PlutoTV/xx.xml.gz`) |

Only country codes that have **both** files verified are listed in the UI. VOD playlists (`pluto-vod-*`) are ignored.

| Option | Purpose |
| --- | --- |
| Catalog / Country | Regional catalog to import. Add one addon instance per country. |
| Timeout | Download timeout for M3U/XMLTV |
| EPG Time Shift | Same as XMLTV |
| Test Import | Downloads playlist + guide and reports channel / EPG match counts (does not start streams) |
| Resources | Catalog, Meta and Stream by default |

### Region and playback

You can import catalogs from different countries. **Playback still depends on regional availability of the streams** (JWT URLs in the M3U often encode a country). Choosing a catalog does not change your player’s IP.

Stream URLs include short-lived JWTs. AIOLiveTV keeps the latest M3U in cache, resolves by stable channel id at tune time, and may refresh the playlist once if the JWT looks expired. It does **not** mint tokens itself.

On Brazil (`pluto-live-BR.m3u` + `PlutoTV/br.xml.gz`) we measured a full `tvg-id` ↔ XMLTV `channel id` match and successful HLS through a media segment without a dedicated proxy.

| Env | Default | Effect |
| --- | --- | --- |
| `PLUTOTV_ENABLED` | `true` | Disable the provider for everyone on this instance |
| `PLUTOTV_DISABLED_REASON` | English admin message | Shown when Pluto TV is disabled |

Internal ids are `pluto:{region}:{originalId}`. Catalog `tvg-id` keeps the original Pluto id so M3U and XMLTV stay aligned for export.

## Other live sources

### Spain

Three independent builtins are available on the Addons page:

| Builtin | Resources | Metadata |
| --- | --- | --- |
| Orange TV | Catalog + Meta | Guide, synopsis, genres, classification, artwork, cast and directors when available |
| Movistar Plus+ Spain | Catalog + Meta | Guide and detailed programme information from Movistar Plus+ Spain |
| TDTChannels | Catalog + Meta + Stream | XMLTV guide and streams from [LaQuay/TDTChannels](https://github.com/LaQuay/TDTChannels) |

Orange TV and Movistar Plus+ Spain are guide providers. Bind their channels to TDTChannels, M3U, Xtream or another stream addon on Channels. Adding these providers does not grant access to Orange or Movistar subscription streams.

All three use the existing timeout, resource selection and EPG Time Shift options. Spanish age classifications use [CNMC icons from age-rating-kit](https://mrcanelas.github.io/age-rating-kit/#cnmc). Extra programme details are optional: the basic schedule remains available if a detail request fails.

Native EPG is advertised only after programme data has been verified. TDTChannels uses the XMLTV channel definitions when a guide is available, and falls back to playlist channels and streams when it is not. Configuration and channel mappings remain in the draft until Save.

### Other providers

- **RTVE** - community addon for Spanish live TV, added through the same external-addon flow as USA TV, Fenix TV and FrostView. Catalog, metadata and streams can be selected independently. Radio and RTVE Play are excluded from this Live TV preset. Some streams are restricted to Spain. Source: [Pigamer37/rtve-stremio-addon](https://github.com/Pigamer37/rtve-stremio-addon).

- **Vivo TV** and **Claro TV+** — Brazilian guide metadata (Claro needs `CITY,STATE`). Pair them with M3U or Xtream for playback.
- **Mi.tv** — Latin American guide metadata. Choose the country when adding the addon; add one instance per country.
- **USA TV, Argentina TV, FrostView, Debridio TV** — community live addons with the usual URL / timeout options.
- **Custom addon** — any Stremio manifest that exposes live `catalog` / `meta` / `stream`.

## Matching

EPG is the reference when it exists. Otherwise channels are inferred from stream sources.

Automatic matching only applies at **high confidence** (≥ 0.9), in this order:

1. `tvg-id` (or the same value as the other side's channel id)
2. Normalised name
3. Aliases
4. Country, language, categories, logo (small boosts)

Partial name hits stay as **suggestions** on the [Channels](/guides/channels) page. You can always override with a manual mapping.

Resolution, language and codec suffixes (`HD`, `FHD`, `H265`, …) are stripped when comparing names so `AMC FHD` can bind to `AMC`.
